Right from the start I wanted to host LoomClone on European servers run by European firms, and [Hetzner](https://www.hetzner.com/) is the obvious first choice (I already use them to host a [minecraft box](/notes/minecraft-bluemap-plugins/#mc-infra)). Rather than giving LoomClone it's own dedicated VPS, I set up a "generic" VPS with some minimal tooling to enable LoomClone to run alongside other services. My thinking here was basically this: if the public surface is behind a CDN, LoomClone is likely to use compute very sporadically (lots when I'm recording videos, almost none when I'm not), and I'm planning to self-host a few other personal services soon (some simplified version of [cal.com](https://cal.com/) and a small [n8n](https://n8n.io/) instance), both of which I expect to *also* use compute very sporadically. Given my expected useage, a single server is gonna be more cost-efective, less of a headache to manage and more fun to noodle about with. So LoomClone is currently running inside a container on a cheap Hetzner VPS, bootstrapped with some [simple tooling](https://github.com/dannysmith/danny-vps-infra/) to set up docker, [Caddy](https://caddyserver.com/) and some niceties if have to SSH in.

## The LoomClone App

To keep things simple server-side the Backend API, Admin Web App and Viewer-facing Surface are all part of a single Hono app. This is backed by a SQLite database and intentionally has very few dependencies. The server is deployed to a cheap Hetzner VPS in Europe as a docker container, with public-facing endpoints behind BunnyCDN.
